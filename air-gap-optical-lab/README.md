# Optical Air-Gap Security Lab

A safe, reproducible implementation inspired by the Science Buddies project
“Hacking the Air Gap: Stealing Data from a Computer that isn't Connected to
the Internet.” The lab models a display-to-camera optical side channel and
measures how distance, brightness contrast, bit rate, and interference affect
binary data recovery.

This is a mathematical simulation. It does not control a real display, record
a camera or microphone, install malware, access a network, or read user data.
Only the synthetic payload `LAB` is transmitted. Results describe the model,
not a physical computer, screen, camera, or human-subject experiment.

## Research question

How do transmitter-to-receiver distance, screen-brightness contrast, bit rate,
and environmental interference affect packet recovery and bit error rate in a
simulated optical channel from an air-gapped computer?

## What the model includes

- A framed binary packet with a preamble, payload length, synthetic payload,
  and CRC-8 integrity check
- Binary amplitude modulation using two brightness levels
- Inverse-square optical signal loss as distance increases
- Deterministic sensor noise representing quiet, moderate, and high
  interference
- Increased model noise at higher bit rates to represent shorter exposure time
- Packet recovery rate, bit error rate, signal-to-noise ratio, and descriptive
  contrast bands

The model deliberately omits malware, operating-system display manipulation,
camera capture, real files, and physical-device control.

## Requirements

- Python 3.10 or newer
- No third-party runtime packages

## Run the completed experiment

From this directory:

```powershell
python optical_channel_lab.py experiment `
  --trials 10 `
  --seed 20260923 `
  --output reports/results.csv `
  --summary reports/summary.json
```

This performs 1,350 trials: five distances, three contrast levels, three bit
rates, three interference levels, and ten repetitions per scenario. The
committed CSV and JSON files were generated by that command.

Run one harmless demonstration:

```powershell
python optical_channel_lab.py demo `
  --distance 3 `
  --contrast 3 `
  --bit-rate 5 `
  --interference quiet
```

## Test the implementation

```powershell
python -m unittest discover -s tests -v
```

The 19 tests cover protocol framing, CRC validation, bit conversion, parameter
validation, inverse-square attenuation, noise behavior, repeatability,
experiment aggregation, file outputs, and both command-line workflows.

## Representative results

The table isolates one controlled slice: 3% contrast, 1 bit/s, quiet
interference, and ten trials per distance.

| Distance | Packet recovery | Mean bit error rate | Mean model SNR |
|---:|---:|---:|---:|
| 0.5 m | 100% | 0.0000 | 670.820 |
| 1.5 m | 100% | 0.0000 | 74.536 |
| 3.0 m | 100% | 0.0000 | 18.634 |
| 6.0 m | 80% | 0.0042 | 4.658 |
| 9.0 m | 0% | 0.1646 | 2.070 |

The model shows why an air gap is not the same as perfect isolation: a physical
emanation can carry a signal, but reliability falls as distance and noise rise.
A CRC failure also demonstrates that receiving some recognizable bits is not
the same as recovering an intact packet.

## Optional physical follow-up

A separate, consent-based classroom follow-up may use a screen displaying only
synthetic patterns and a phone light sensor. Do not install malware, access
private data, conceal recording, alter school or workplace equipment without
permission, or use heat and fan stress methods on valuable hardware.
